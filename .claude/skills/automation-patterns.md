# automation-patterns

> 이 스킬은 자동화 패턴과 AI 트렌드 스카우팅 도메인 지식이다.

## 자동화 기회 탐지

```
반복 패턴 인식 → 자동화 가능성 → 도구 선정 → 구현

반복 작업 3회+ → 자동화 후보 식별 → 빌더에게 사양 전달
```

## 자동화 대상 분류

- **즉시 자동화**: 명확한 규칙 기반 + 반복적 + 검증 가능
- **부분 자동화**: 규칙 기반이지만 예외 처리 필요
- **사람 보조**: 판단·창의·관계 영역 (자동화하지 않음)

## 4채널 운영 자동화 후보

- 등록 양식 자동 변환 (4채널 규격 변환)
- 재고 동기화 알림
- CS 자동 분류 + 표준 답변 초안
- 정산 자동 집계
- 가격 변동 감지

→ 모두 SaaS 기능으로 전환 가능 ("멀티채널 등록 자동화", "AI 재고 관리", "AI CS 자동 응대", "자동 정산 리포트")

## AI 트렌드 스카우팅 (PB-9)

**탐색 대상**:
- GitHub 오픈소스: MCP 서버, LangGraph/CrewAI 플러그인, AI 에이전트 패턴, 프롬프트 도구
- 새로운 AI 프레임워크·라이브러리 릴리스
- 커뮤니티 베스트 프랙티스 (LangChain Hub, CrewAI Templates 등)

**탐색 주기**: 매 구현 작업 시 1회 이상 (Q5 점검). 본업 지연 금지.

## 도입 프로세스 (4단계)

```
1. 발견: "이런 도구/패턴이 있다"
2. 적합성 판단: "우리 자비스에 맞는가?"
3. 변형 설계: "수정 필요한 부분은?"
4. 제안서 작성: 무엇을 / 왜 / 어떻게 / 예상 효과 / 리스크
```

## 트렌드 제안 두 트랙

- **트랙 1 — 구현 레벨**: 더 나은 라이브러리, 성능, 버그 방지 패턴 → 디렉터(planner)
- **트랙 2 — 구조급**: 새 MCP 서버, 프레임워크, 아키텍처 → planner (기획)

판단 헷갈리면 둘 다에게.

## 제안서 형식

```
[기술명] / [버전] / [출처 링크]

문제 해결: 어떤 문제를?
도입 방법: 어떻게 우리 시스템에 붙이는가?
예상 효과: 정량(시간/비용 절감) + 정성(품질 향상)
리스크: 의존성, 유지보수, 비용
대안: 다른 선택지
```

## 자동화 전후 비교 데이터 축적 (OB-SAAS-02)

```
예: 등록 작업 자동화 전후
- 전: 1상품 등록 160분
- 후: 1상품 등록 20분
- 절감: 87.5%

→ SaaS 마케팅 자산
"콘텐츠 제작 시간 80% 줄인 사례"
```

## 자동화 파이프라인 예시

### 등록 파이프라인
```
product-md 기획 → content-marketing 상세페이지 →
commerce-ops 4채널 등록 지시서 → 사람 실행 →
data-analytics 등록 완료 데이터 수집
```

### 일간 리포트 파이프라인
```
채널별 데이터 수집 (자동) → 정합성 점검 (자동) →
KPI 계산 (자동) → 이상치 감지 (자동) →
data-analytics 일간 리포트 생성 → 대표님 알림
```

### 조기 경보 파이프라인
```
선행 지표 모니터링 (자동) → 트리거 조건 충족 시 발동 →
data-analytics 경보 보고서 생성 →
대표님 + planner 즉시 알림
```

## CBT 패턴 (트렌드 탐색 시)

- 오버엔지니어링 충동 → "현재 Stage 적정한가?" 점검
- 새 도구 도입 충동 → "기존 80% 가능한가?" 충분하면 보류
- 트렌드 과몰입 → "본업 지연되고 있지 않은가?" 점검
